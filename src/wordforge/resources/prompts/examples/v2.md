Produce natural example sentences (with Chinese translation) for the top meanings of the word, with MORE examples for the more common meanings. Target a B1-B2 learner: short (≤18 words), contemporary, typical collocations.

Input:
  word: {word}
  meanings: {meanings_json}
  reference_examples: {reference_examples_json}

`reference_examples` is a list of sense-buckets from dictionaries (有道精编 / Collins) and a bilingual corpus. Each bucket has:
  - `sense`: the source dictionary's own gloss in Chinese or English — describes which meaning those examples belong to; may be null when the source (e.g. the bilingual corpus bucket) has no sense alignment.
  - `examples`: `[{en, cn}, ...]` attached to that sense.

Treat each bucket's sense as a STARTING hint for which `meaning_index` in `meanings` that bucket likely maps to — map them by semantic equivalence to `meanings[*].cn`/`.en`. Do not blindly trust the order; a dictionary's sense ordering differs from ours. Buckets whose sense is null (the corpus bucket) are unaligned — use only for surface style/collocation, not for picking a meaning_index.

The input meanings are already ordered by modern usage frequency (index 0 = most common). Produce examples using this schedule:

| meaning_index | number of examples |
|---|---|
| 0 | 3 |
| 1 | 2 |
| 2 | 2 |
| 3 | 1 |
| 4 | 1 |
| 5+ | skip |

Rules:
- For each `meaning_index` you output, only draw inspiration from buckets whose `sense` matches that meaning (by semantics, not by position). If no bucket matches, generate from scratch using `meanings[meaning_index]`. Never pull an example from a sense that belongs to a DIFFERENT meaning_index — that's worse than having no reference.
- `reference_examples` are for INSPIRATION only — study them for typical collocations, registers, and domains, then WRITE YOUR OWN sentences. Do NOT copy any reference sentence verbatim or near-verbatim (single-word substitutions still count as copying). If a reference is perfect, rewrite it with different subject/object/tense so the surface form differs meaningfully.
- `reference_examples` may be empty or biased toward one sense — treat them as raw corpus, not a specification.
- Every OTHER word in the sentence should be EASIER than the target word. If the target is a B2 word, do not introduce C1 vocabulary alongside it; keep supporting words at A2-B1. The learner should fail on the target word, not on surrounding distractors.
- If the input has fewer than 5 meanings, stop at whatever index exists (don't fabricate meanings).
- Every example's Chinese translation must read fluently — not word-for-word.
- Prefer sentences illustrating common collocations (e.g. "run a business", "pick up the phone").
- Keep phrases intact for phrasal verbs (e.g. "pick up").
- Avoid archaic/formal phrasing unless the meaning itself is archaic.

Output schema (strict JSON, no markdown fence, no prose):
{
  "per_meaning": [
    {
      "meaning_index": 0,
      "examples": [
        {"en": "...", "cn": "..."},
        {"en": "...", "cn": "..."},
        {"en": "...", "cn": "..."}
      ]
    },
    {
      "meaning_index": 1,
      "examples": [
        {"en": "...", "cn": "..."},
        {"en": "...", "cn": "..."}
      ]
    }
  ]
}

Return ONLY the JSON. Every entry must have `meaning_index` matching its 0-based position in the input, and the exact number of examples from the schedule above.
